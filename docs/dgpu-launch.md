# Launch Using Dedicated Graphics Card

On hybrid GPU systems, the app launchers (Kickoff, Kicker, Application
Dashboard) and the task manager show **Launch Using Dedicated Graphics Card**
in each app's context menu. That includes laptops with an eGPU plugged in.

## How it works

- **The action:** Plasma's launchers load drop-in actions from
  `share/plasma/kickeractions/*.desktop` for every app, passing the app's desktop
  file as `%u` ([plasma-workspace!1355](https://invent.kde.org/plasma/plasma-workspace/-/merge_requests/1355)).
  [`../dgpu-launch/data/ultramarine-dgpu-launch.desktop`](../dgpu-launch/data/ultramarine-dgpu-launch.desktop)
  runs `switcherooctl launch kioclient exec %u`. switcheroo-control sets the
  discrete GPU's environment (`DRI_PRIME`, NVIDIA PRIME offload variables,
  `VK_LOADER_DRIVERS_SELECT`), and kioclient starts the app the same way Plasma does,
  in its own `app-*.service` unit.
- **Task manager:** upstream only reads drop-ins in the launchers. The
  [`../plasma-desktop/`](../plasma-desktop) patch makes the task manager show
  them too. It changes one function and has no QML changes. It should be upstreamed.
- **Only on hybrid systems:** `/usr/share/plasma/kickeractions/ultramarine-dgpu-launch.desktop`
  is a symlink to `/run/ultramarine-dgpu-launch/ultramarine-dgpu-launch.desktop`.
  `ultramarine-dgpu-detect` creates that link only when the default (`boot_vga`)
  GPU isn't discrete and another GPU is. Discrete means switcheroo-control's
  `switcheroo-discrete-gpu` udev tag. Otherwise the symlink is broken, and Plasma
  skips broken symlinks: it lists the directory with `QDir::Files`.
- **Hotplug:** `90-ultramarine-dgpu.rules` restarts `ultramarine-dgpu-detect.service`
  when a DRM card is added or removed, which covers coldplug at boot and plugging in or
  removing an eGPU. The menus are built each time they open, so changes show up
  without restarting Plasma.

| Setup                                        | Shown |
| -------------------------------------------- | ----- |
| Laptop, iGPU + dGPU                          | yes   |
| Laptop + eGPU                                | yes   |
| Desktop, single dGPU                         | no    |
| Desktop, iGPU enabled but display on the dGPU | no    |
| Two dGPUs, no iGPU                           | no    |
| iGPU only                                    | no    |

## Patch versions

- [`../plasma-desktop/6.8/0001-taskmanager-show-launcher-drop-in-actions.patch`](../plasma-desktop/6.8/0001-taskmanager-show-launcher-drop-in-actions.patch):
  plasma-desktop 6.8.x (builds against 6.8.2, applies to 6.8.1 and master); for UM45.
- [`../plasma-desktop/6.7/0001-taskmanager-show-launcher-drop-in-actions.patch`](../plasma-desktop/6.7/0001-taskmanager-show-launcher-drop-in-actions.patch):
  plasma-desktop 6.7.5, for testing on UM44.

There's one directory per Plasma minor version. um-packages ships it as `ultramarine-plasma-desktop`, which provides, conflicts with and
obsoletes Fedora's `plasma-desktop` and its subpackages, so it replaces Fedora's even
though the `kde-desktop` comps group still lists `plasma-desktop`. Its spec is
generated by `update.rhai`. Don't edit the spec by hand:

1. Get the **stable** plasma-desktop build for the release from Bodhi. Stable is
   what's in our buildroot; dist-git and updates-testing can be ahead of it.
2. Get that build's dist-git commit from Koji, then Fedora's spec, `sources`
   and any patches Fedora carries at that commit.
3. Take `plasma-desktop/<major.minor>/` from `main` here and check that it applies to the
   tarball with `--fuzz=0`, like rpmbuild does. If it doesn't apply, or there's no
   directory for a new minor version yet, nothing changes until it's rebased.
4. Write Fedora's spec with `Patch300` added, lookaside sources turned into URLs, and
   `Release: <fedora>%{?dist}.N`. N resets for a new Fedora build and goes up when
   only our patch changes, so we always sort above Fedora's build.

Fedora's spec changes (new files, BuildRequires) come along on their own. The only
manual work is rebasing the patch here.

The patch only touches `Backend::jumpListActions()` in
`applets/taskmanager/backend.cpp`. That function hasn't changed from 6.7 through master,
so expect a rebase about once per Plasma minor version, if at all.

## Limits

- Single-instance apps that are already running (Firefox, Discord, most Electron
  apps) hand off to the running copy, so they stay on the GPU they started on.
- Flatpak apps get the environment through `flatpak run`, so this works as long
  as the app has GPU access (`--device=dri`).
- Users can hide the action by placing a file named `ultramarine-dgpu-launch.desktop` with no
  `Actions=` in `~/.local/share/plasma/kickeractions/`. User files shadow system
  files with the same name.

## Testing

```bash
# Is this machine hybrid? (exit 0 = shown, 1 = hidden; changes nothing)
/usr/libexec/ultramarine-dgpu-detect --check

# What the action runs, by hand:
switcherooctl launch kioclient exec /usr/share/applications/org.kde.kwrite.desktop
tr '\0' '\n' < /proc/$(pgrep -n kwrite)/environ | grep -E 'DRI_PRIME|NV_PRIME|VK_LOADER'
```

Plasma looks up `share/plasma/kickeractions` the first time a launcher menu opens.
After the first install, restart plasmashell once.
